# 帖子流与阅读布局

2026-10-05 用户确认继续优化模块辨识度与交互，并沿用三行帖子流、单列详情和列表评论数先省略的取舍。模块交互验证见[界面与交互验证](verification/ux-polish.md)；最新发布入口位置及配色见[验证记录](verification/publish-entry.md)。当前设计替代此前的黄色字标、账号卡和双行列表方案。实现见 `src/`，静态示例见[视觉评审稿](visual-preview.html)，验收范围见[验证记录](verification/post-stream.md)。

## 设计取舍

视觉焦点落在帖子标题与正文：首页采用连续帖子流，详情采用单列阅读。移除主内容外框、账号卡和热门排行表格；热门内容直接放在浅灰页面底上，不再切成重复卡片。色彩只用于链接、选中状态与必要操作，不用黄色品牌块抢占标题的注意力。

使用用户截图明确要求的三行结构和作者／时间分隔符。取消独立排名数字、实心发布横条与社区胶囊；通过字号、内容间距和位置区分层次。品牌名定为 Ripple，保留为弱化的文字标识。

| 页面底 | `#F7F8FA` |
| 阅读底 | `#FFFFFF` |
| 标题与正文 | `#252A34` |

| 分隔线 | `#E8ECF1` |

输入控件边界 `#8490A0`，选中浅底 `#EEF2FA`；成功、警示和危险沿用已有语义颜色。辅助文字在白底和页面底保持至少4.5:1，输入边界在两种底色均超过3:1；选中投票同时有状态文字及 `aria-pressed`。

字体栈以 PingFang SC、Microsoft YaHei、Noto Sans CJK SC 为中文字体，随后回退系统无衬线。无需下载字体或新增依赖。列表标题17px/26px、400字重，作者与时间13px/20px，社区12px/20px。详情标题30px/1.45、600字重；正文16px/1.85，最多75ch；评论正文15px/1.8。

品牌采用用户选定的 C 偏弧字标：`public/wordmark.svg` 为手绘路径，沿用辅助文字色 `#687180`；`e` 横笔略倾斜、末端上扬。顶栏和登录／注册页保留原文本占位（17px、500字重，手机16px），覆盖26px高的装饰图像，链接名称为“Ripple 首页”。字标不改变原占位和周围留白，无背景或边框。标签页图标 `public/favicon.svg` 为灰蓝 `#52627C` 的不规则圆润轮廓，没有字母或具象符号。只保留最终通过的品牌版本，验证结果见[品牌验证](verification/brand-c.md)。

按钮改8px圆角，主要提交用克制的蓝色；浏览页的发布入口位于帖子列表顶部，使用浅灰底 `#F3F5F8`、灰蓝文字 `#52627C` 和控件边界 `#8490A0`，保持44px高；悬停使用 `#E8ECF1` 浅底。菜单发布使用同样配色。侧栏仅保留热门讨论，标题16px/26px、600字重，正文15px/25px。取消、回复、清空草稿和删除入口使用轻量文字操作。删除确认保留危险色。

## 首页与社区布局

容器最大1200px（含左右24px），内部最大1152px。顶栏最小72px，真实社区导航使用深色文字、柔和选中背景及蓝色底线，可水平滚动；账号入口位于右侧，游客登录采用明确描边按钮。内容区顶部32px，帖子流最大844px、侧栏260px，两栏间距48px。白色帖子流不加外框、阴影或卡片圆角。

```text
Ripple     全部帖子  社区名称…                         账号
─────────────────────────────────────────────────────────
全部帖子            最新  最热  发布帖子          热门讨论

投票验收新帖                     前沿快讯       帖子标题
votev7a · 5 分钟前                               帖子标题
                                                社区  时间
─────────────────────────────────────────       帖子标题
下一篇帖子                                      社区  时间
```

桌面帖子行上下16px、左右24px，各行间隔5px；社区与标题顶部对齐。标题链接的点击范围覆盖整行，社区链接独立在其上层，不被遮挡，键盘焦点可见。完整标题自然换行，长英文可断行；社区名称最大120px。列表接口不返回票数，列表与热门讨论均不展示票数，也不逐帖读取详情补齐。桌面工具栏最小64px，依次显示浏览范围、最新／最热、发布帖子；发布点击保存来源及列表位置。手机将范围放在第一行，排序与发布同在第二行；异常重试、删除后追加暂停时的“从第一批刷新”继续可用。

热门讨论取服务端热度顺序前五帖。标题最多显示两行，下面显示社区与相对时间；项目间距22px，模块标题与正文使用深色文字，没有排名数字或票数表头。继续复用 `postsListQueryOptions(null, 'hot')` 和共享缓存，不根据净票重新排序。

## 时间与接口边界

列表和热门讨论按浏览器本地日历显示时间：当天为“刚刚”、整数分钟或小时；前一天为“昨天”；更早为“10 月 3 日”，跨年补年份。午夜跨日优先使用“昨天”，不要求距当前满24小时。未来时间用日期，非法值保留原始值。

列表时间元素保留 `dateTime`，悬停提示完整时间；详情、评论及社区创建时间继续展示完整日期与时分。相对时间在渲染时计算，不触发额外请求或自动重排列表。

现有列表契约没有评论总数，用户明确同意先省略：不虚构总数，不逐帖请求评论列表，不改后端或生成类型。

## 详情与讨论

详情和发帖页采用单列，外层最大880px，阅读区左右36px、正文最多760px。详情不挂载论坛侧栏，也不为隐藏热门内容发请求。

```text
返回帖子列表 / 社区

帖子标题
作者                                      删除帖子
完整时间
──────────────────────────────────────────
正文、引用、列表与代码块

赞成 2    反对 1    取消投票
当前方向或提交结果提示
──────────────────────────────────────────
评论                         写评论    刷新
作者  完整时间  评论编号
评论正文与回复引用
回复   删除

参与讨论
评论输入区
发表评论                              清空草稿
```

标题和作者区之后用一条分隔线进入正文；正文上下32px。投票计数放进对应按钮，默认投票按钮使用可辨识的控件边界；确认方向采用浅蓝底、蓝边框、勾选图标与文字，提交时显示旋转图标及提交提示并禁用重复操作，未知方向不冒充未投票；取消为次要操作。原有认证、提交、失败分类与回显不变。

评论与回复维持整页滚动、按服务端顺序平铺。引用采用浅底与左侧线，评论正文与动作沿同一轴对齐。编辑区使用浅灰输入底、明确标签与蓝色提交；游客区显示“参与讨论”和“登录后评论”按钮。“写评论”定位输入区，游客则定位登录提示，不清除已有回复目标。输入区获得焦点或清空确认打开时暂停自动追加评论，离开后恢复，避免追加把输入框推出视口。回复定位时保留正文，回复目标用蓝色左线与浅底强调。确认框16px圆角，仅模态弹层使用轻阴影；原生 dialog 继续管理焦点与 Escape。

## 响应式与可访问性

768–1023px：卸载侧栏；保留顶部社区导航，发布在列表顶部直接可用，账号进入菜单。小于768px：顶栏保留字标和描边菜单按钮；菜单依次提供发布、社区、账号，当前社区有浅底及左侧蓝线。列表标题占满第一行，作者与时间位于第二行，社区独占第三行并左对齐；社区点击区域至少44px高。左右边距16px，列表标题16px/24px、社区12px，详情标题25px/36px；正文左右16px。手机评论输入16px，避免小字体触发输入缩放。

菜单发帖保存来源社区、排序和列表滚动位置，点击后关闭。窗口扩大至1024px关闭窄屏菜单。主要操作至少44px高，焦点始终可见；减少动态效果偏好生效。仅使用150ms颜色反馈，不新增自动动画。

控件变体由 Tailwind utilities 控制；布局、排版由语义组件类控制。投票选中颜色显式使用 `aria-pressed:` utilities，避免组件层样式被按钮基础 utilities 覆盖。

## 登录返回、表单与草稿

内容页登录／注册入口记录当前地址；登录完成后回到原页面，列表排序和位置继续按现有内存规则恢复。`from` 表示登录后目标，`listFrom` 携带原列表来源；RequireAuth 与注册往返继续传递两者，恢复目标时把列表来源交回内容页的 `from`。两种地址都经 `safeRedirectTarget` 校验，不自动提交先前动作。认证策略、令牌和缓存协议不变。

发帖无草稿时预选来源社区，先确认社区仍在当前列表中；有草稿时使用草稿，即使其社区为空也不覆盖。修改字段后清除对应本地错误；网络写入结果未确认的警示继续保留。

帖子与评论统一使用“清空草稿”。有内容或恢复的草稿才允许清空；先确认，默认聚焦“继续编辑”，Escape 保留内容。确认后清除对应标签页草稿并聚焦标题／评论输入框。发帖保留有效来源社区作为初始选择。

## 2026-10-08 接口适配

作者读取 `author_username`。桌面列表保留标题／社区和作者／时间两行；
手机仍为标题、作者／时间、社区三行。详情的实时票数来自 MySQL，投票
成功只更新详情票数，不向列表缓存塞入不存在的字段或重排列表。

本人方向读取经现有会话模块携带 Bearer；游客和身份恢复中不读取。
方向 0 显示“未投票或已取消”。写入结果未知时清除旧方向、仅重新读取确认；
读取失败保持未知，不自动重复 PUT。投票无七天限制。

帖子短页／空页允许继续按页码与 total 加载；空页的追加失败同样显示重试，
不误显示“还没有帖子”。评论仍使用原始条数判断尾页。异步排行造成的
可见性、total 与顺序短暂滞后，以及并发页码分页漏读，前端不承诺消除。

正文与评论分别限 10,000／2,000 个 Unicode 字符，表单显示计数和字段错误，
超限不提交、不截断并保留草稿；修改字段清除本地旧错误。后端 `a173d1b` 已补齐 OpenAPI
长度上限，最终快照保持与后端一致，来源记在 `openapi/README.md`。
