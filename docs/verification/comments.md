# 评论与回复验证记录（Issue #6）

契约：前端快照 SHA256 `6539ce9aa42e0a4e1a02828008d5a5bf582495dcac6acb4efa299fc6b05cd0d0`。评论列表、创建和删除路径与 OpenAPI 一致。后端只读，没有改它。

## 用户行为

- 游客可以读评论。列表按服务端的创建时间、再按 ID 升序平铺。回复是同一帖子上的评论，不是另一套内容。评论按纯文本显示，不解析 Markdown 或 HTML。正文和评论跟着整页滚动，评论区自己不出现纵向滚动条。
- 每页 10 条。接近底部追加下一页。结束和下一页用响应里的 `page`、`page_size`（必须是 10）、`total` 和原始 `items` 长度，不用去重后的条数。同一 ID 只保留第一次出现的顺序。
- 列表键是 `['comments', 帖子 ID]`。公开查询，退出或换账号不清除。第一页暂时失败会再请求一次；追加、发表、删除和末页核对都不自动重试。窗口聚焦、网络恢复和重新挂载不重取已加载页。
- 回复目标已经在已加载列表里时显示引用。还没加载到只显示编号。后面的页把目标带进来后再显示引用。缓存里没有不能叫已删除。只有这次浏览里确认删除过的 ID 才标成已删除。
- 发表和回复要登录。登录后回到原来的帖子，不自动提交。可以选同一帖子里的评论当目标。换目标时正文留着，并标明新目标。服务端用 `INVALID_PARAMS` 拒绝这个目标时，输入留着，发表停用，提示改选或改为直接评论。这不把目标标成已删除，也不把别的参数错误都说成目标失效。
- 草稿键 `bluebell:draft:{用户 UUID}:comment:{帖子 ID}`，存在当前标签页，包含回复目标。刷新后还在。成功或放弃才清这份草稿。主动退出按账号前缀清掉该账号的草稿。最终失效不走这步清理。
- 发表中按钮锁定，写入不自动重试，也不重放。结果未知时留下输入。旧会话的回调对不上当前账号和会话时，不导航、不把回显安到新账号、也不清掉新草稿。提交之后又改过的草稿，成功回调不清掉。
- 创建只返回 ID。回显用这个 ID、刚提交的正文和回复目标，不造时间，也不造一条完整的服务端评论。写成功但紧接着的列表核对失败时，两句分开说。
- 没读到底时，回显放在编辑区附近，不把后面的页拉过来。读到同一个 ID 后合并，回显拿掉。已经读到底时，先核对当前最后一页，再只追加紧邻的下一页。末页不满和末页刚好满都这样做。不把更后面的页接到缺口上。
- 只有 `author_id` 等于当前用户 UUID 时显示删除。帖子作者不能删别人的评论。页内确认，不是浏览器弹窗。204 去掉这条评论和它的回显，回复留着，并暂停这篇帖子继续追加。从第一批刷新会重新从第 1 页加载，并滚到评论区，正文和草稿还在。当前回复目标被确认删除后，要重选或明确改为直接评论。迟到的旧页即使还带着这条评论，也不再显示它。

## 真实接口与浏览器验证（2026-10-04）

环境：MySQL `127.0.0.1:3306` 与 Redis `6379` 已在监听，后端 `go run ./cmd/server`（`:8080`），Vite `127.0.0.1:5173` 代理 `/api`。浏览器为 playwright-cli 的 Chromium。使用账号 `commentv6a` 与 `commentv6b`。社区 1「前沿快讯」。帖子 29「评论验收帖」、30「满页核对帖」、31「未读到底帖」、32「整页续载帖」。
