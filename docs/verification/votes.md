## 用户行为

- 只有帖子详情在身份确认后才读取本人方向。游客和帖子列表不发这个请求。列表行只显示公开的赞成数和反对数。
- 缓存键是 `['votes', 帖子 ID, 'account', 用户 UUID, 本次会话]`。续期沿用这次会话。访问令牌不在键里。退出和换账号清掉这个账号的方向，帖子列表、详情和评论还在。
- 1 是已赞成，-1 是已反对，0 是还没投或已取消。加载中、失败，或还没有本人方向，都显示未知，不写成未投票。
- 三个按钮分别是赞成、反对、取消投票。取消是单独的动作。当前方向用 `aria-pressed` 标出；未知时三个都不是按下。
- 游客点任何一个按钮进入登录，并带上这篇帖子的地址。登录回来停在原帖，不自动投票。
- 提交过程中三个按钮不可用。写入不自动重试，重新登录后也不重放。网络故障或 5xx 提示结果未确认。`409 / VOTE_CLOSED` 提示投票已结束，并停用当前这篇帖子、这一次登录的三个按钮。换到别的帖子、退出或换账号后，结束提示和停用清掉。迟到的回调不写到新页面。回到原帖再写仍由服务端决定。
- PUT 成功后，方向用回显写入这次登录。再读公开详情，按 ID 更新已加载列表和详情的票数，顺序不变，也不重取整个列表。详情读失败时方向留下，页面同时说明投票已记录和票数还没更新，不重发投票。
- 回调时会话已经变了，不写新会话的方向，也不把这次详情填回去。
- 当前后端的查询接口不识别访问令牌。带令牌投完赞成后再查，仍是 `direction: 0`。详情页因此先不发 GET。方向只来自这次登录中的 PUT 回显。刷新页面后回到未知，即使票数还在。`voteDirectionReadIdentifiesUser` 仍是 false。

## 收底（2026-10-04）

三个投票按钮改由同一份动作列表渲染，名称、`aria-pressed` 和点击行为不变。GET 与 PUT 的回显共用一次方向解析。帖子模块记录里的「投票写入仍归后续模块」改成指向投票模块一节。查询接口仍不识别访问令牌，`voteDirectionReadIdentifiesUser` 仍是 false。

`pnpm test` 仍是 13 个文件、203 项。`pnpm lint` 0 error，3 条既有 warning。`pnpm typecheck` 通过。浏览器：游客在帖子 35 看到三个按钮，点赞成进入登录，票数仍是赞成 1、反对 0。`votev7a` 登录回来后没有自动投票，方向未知。赞成后是「你已赞成」，票数赞成 2、反对 0，只有赞成按下。取消后回到赞成 1、反对 0，「你还没有投票」，取消按下。没有 GET `/vote`。390 宽没有整页横向滚动，按钮高度 36。
