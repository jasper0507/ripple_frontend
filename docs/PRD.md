# Ripple 产品视觉与交互需求

版本：后端同步实现稿 1.7，2026-10-08。读者：产品、设计、验收人员。

本轮在当前前端仓库实施首页与详情重设计，用户已确认方案并选择列表评论数先省略。模块层级和交互优化已实施；用户后续要求发布换色并移至列表顶部，当前验证见[发布入口记录](verification/publish-entry.md)，当前组件示例见[视觉评审稿](visual-preview.html)，实现人员另读 [DESIGN](DESIGN.md)。评审稿为示例内容，不连接接口。

## 一 事实与范围

以现有前端API契约、业务代码和运行结果为依据。本轮禁止修改后端，不新增接口或依赖；当前目录没有可用Git HEAD，本轮使用 `/tmp/bluebell-ux-baseline` 比对源码。历史论坛视觉见[旧验证](verification/forum-redesign.md)。

用户要求三行帖子列表、去掉顶部刷新与发帖、减少卡片、弱化Logo和社区名称、现代化顶部导航、列表相对时间、精简热门讨论，并重新设计整个详情页。该要求替代此前黄色品牌、账号卡和双行列表方案。

后端在研究期间已经取消投票时间窗口和个人明细到期删除。最终方案不显示七日截止、倒计时或“投票已结束”。GET 投票状态已恢复鉴权；登录用户打开详情或刷新后读取本人方向，0 表示未投票或已取消，读取中或失败保持未知。

| 保留的现有能力 | 本轮调整 | 不增加的能力 |
| --- | --- | --- |
| 游客阅读；注册登录；社区；最新/最热；发帖；投票；评论回复；本人删除 | 颜色、排版、导航、内容布局、表单层次、反馈样式、可访问性 | 搜索、关注、收藏、通知、头像上传、编辑帖子、个人主页、社区管理 |
| Markdown 帖子、纯文本评论、草稿隔离、滚动加载与返回位置恢复 | Markdown 阅读样式、回复引用、草稿提示及加载提示位置 | 新富文本编辑器、上传能力、服务端草稿、无限嵌套回复 |
| 已有请求、认证、缓存和路由 | 使用现有状态呈现更清楚的交互 | 替换认证策略、迁移框架、重新生成一套业务架构 |

## 二 当前体验与目标

以下是基于代码的设计评估，未把它称为用户访谈或实机可用性测试。

| 本轮审查发现 | 对体验的影响 | 已实施的调整 |
| --- | --- | --- |
| 发布按钮、热门标题及导航均过淡 | 次要模块与普通说明文字难区分 | 列表顶部浅灰发布按钮、深色模块标题及明确导航选中状态 |
| 手机隐藏当前社区，社区名称挤占标题 | 当前范围不清，标题多换行 | 工具栏显示范围，手机标题满宽、社区独占第三行 |
| 长简介默认展开 | 帖子列表被推到首屏下方 | 超过240字默认收起，操作名称反映当前状态 |
| 登录未完整保留来源 | 用户返回首页或发帖时重复选择社区 | 当前页面及列表来源贯穿登录注册，草稿优先于社区预选 |
| 输入区位于评论之后，快捷定位会触发分页 | 想评论需要长距离滚动，定位后输入区又被推走 | 写评论快捷入口，编辑期间暂停自动追加 |
| 清空草稿一步执行，旧字段错误持续显示 | 容易误清空，修改后的反馈不清楚 | 清空确认、取消保留、确认后输入焦点，修改字段清除旧错误 |

目标不是虚构转化率：产品评审应能明确识别当前社区和排序、看懂投票状态、知道输入是否保留，并通过键盘或触屏完成既有操作。

## 三 视觉方向

采用暖砂纸底 `#F5F2EB`、暖白阅读区 `#FCFBF8`、深墨色正文 `#1F2120`、沉稳深松绿 `#2D524A` 链接与主提交操作。主阅读区采用 1px 暖色细边框与柔和圆角纸张容器，弱化机械工具感。品牌名定为 Ripple，保留为辅助色文字标识。

系统中文无衬线，列表标题 17.5px/28px（500 字重）、元信息 13px、社区 12px；详情标题 30px（保持无衬线体）、正文 16.5px/1.9；主提交按钮圆角与次要操作胶囊圆角结合，150ms 颜色反馈。普通文字 400 字重，主要标题 600 字重；反馈继续有具体文字与语义颜色。

公共容器最大 1200px（内部 1152px），列表右侧 264px 热门讨论栏、间距 48px。详情／发帖单列，正文最大 760px；小于 1024px 卸载侧栏，账号进入菜单，发布保留在列表顶部，小于 768px 社区也进入菜单。详细尺寸见 [DESIGN](DESIGN.md)。

## 四 页面方案

### P01 公共导航与账号入口

桌面顶栏包含弱化字标、真实社区导航和账号入口，选中社区使用柔和背景及蓝色底线；导航文字保持可辨识的对比度。首页左侧连续帖子流，列表顶部发布入口及右侧热门讨论，没有重复账号卡；热门按服务端热度顺序展示前五项，标题下显示社区与相对时间，不用排名数字或票数列。

站点顶栏没有发布入口；帖子列表顶部与最新／最热一起提供“发布帖子”，采用浅灰底、灰蓝文字和描边。手机将范围放在第一行，排序与发布同在第二行。侧栏只显示热门讨论；手机和平板菜单按发布、社区、账号分组，当前社区有明确标记。菜单发布保存来源社区、排序与列表位置，点击后关闭；详情与发帖保留返回入口。

会话恢复中显示“正在确认登录状态”；暂时无法续期与确定未登录分开呈现。退出失败保留现有会话语义并显示“退出未完成，请重试”，不能显示成功退出，也不擅自改造已接受的会话 ADR。

### P02 首页与社区帖子列表

沿用“最新”和“最热”入口、URL排序与服务端顺序。工具栏显示当前浏览范围与排序。桌面帖子分两行：标题及右侧社区名称；作者与相对时间。手机标题独占第一行，作者与时间位于第二行，社区独占第三行并左对齐。整行可打开帖子，社区仍为独立链接。社区不加胶囊边框。帖子列表已移除票数字段，列表与热门讨论省略票数，不逐帖请求详情补齐；详情页保留真实票数。

评论数先省略。列表契约没有总评论数字段，不虚构总数，不逐帖读取评论接口。完整标题自然折行，长英文可断行，原生链接保留新标签打开能力；桌面17px、手机16px。

当天显示“刚刚 / 2 分钟前 / 37 分钟前 / 3 小时前”，前一天显示“昨天”，更早显示“10 月 3 日”，跨年补年份。使用浏览器本地日历，午夜跨日即切换“昨天”。未来时间显示日期。完整时间保留在 `time` 的机器可读属性与悬停提示，详情展示完整日期与时分。

列表可见性、总数与热度排序由后端异步更新；短页和空页不表示结束，按响应页码与 total 推进，直到覆盖总数；追加失败仍可手动重试。保留滚动加载，不引入页码导航：接近底部按现有逻辑加载下一批，已有内容不闪空；尾部显示“正在加载更多”“重试加载”或“没有更多帖子”。返回列表恢复已加载内容与位置；切换排序或重新建立列表时遵循原有重置规则。已知删除导致追加暂停时，保留“从第一批刷新”入口，不能隐藏已有一致性提示。

### P03 社区页面

社区名称、简介和创建时间来自社区详情接口。简介不超过240字时直接显示，长简介默认收起，操作名称随状态切换“展开简介／收起简介”；空简介显示现有占位。下方直接接社区帖子列表。将“社区不存在”“社区暂时加载失败”“社区中没有帖子”设计为不同状态。

不显示成员数、关注按钮、社区图标上传或社区总帖子数装饰牌。社区名字首字可用作纯前端占位标记，但不声称是后端头像。

### P04 帖子阅读和投票

详情采用单列阅读，不挂载热门侧栏、不请求隐藏列表。返回来源及社区位于标题前；标题、作者和完整时间构成独立阅读头部。保留现有 Markdown 渲染：标题、段落、列表、链接、引用、代码块各有阅读样式；不执行原始 HTML，不加载 Markdown 图片。代码块只在自身内部横向滚动，整页不得横向溢出。

本人删除入口放在元信息附近的次要位置；确认面板说明具体帖子及删除后无法恢复。正文下方提供“赞成”“反对”“取消投票”；票数放入对应方向按钮，取消弱化。默认方向按钮有清楚边界；确认方向使用浅蓝底、边框、勾选图标、`aria-pressed`和现有状态文字；未知状态不选中。

| 投票状态 | 界面表现 |
| --- | --- |
| 游客 | “登录后可以投票”；点击动作进入既有登录流程，回来不自动投票 |
| 方向未知 | 不选中任何方向；“暂时无法确认你之前的投票，可以重新选择或取消” |
| 正在提交 | 三个动作暂时禁用，当前动作显示旋转图标和 `aria-busy`，保留统计和提交提示 |
| PUT 已确认 | 呈现“已赞成”“已反对”或“未投票或已取消”；更新票数 |
| 已确认动作但统计刷新失败 | 保留确认状态，提示“投票已记录，票数暂未更新” |
| 写入结果未确认 | 警示提示，不用总票数推断个人方向；不自动重试 |

当前后端没有时间窗口，因此不按帖子年龄禁用操作，不绘制截止时间。已移除旧截止分支。写入结果未知时只重新读取方向，不重放写请求。

### P05 评论、回复和草稿

沿用整页滚动、从旧到新加载的平铺评论，不增加独立滚动容器或树状层级。作者、完整时间、正文、轻量回复／删除动作沿同一轴对齐；删除仅对本人可见。引用采用浅底与左侧标记，编辑区使用浅灰输入底及蓝色提交。当前改造不显示评论总数：分页流中保存的历史 total 可能在新增或删除后过时。不能用已加载条数代替，也不为帖子列表逐条请求评论数。

回复目标已加载时展示作者和可核实的短引用；未加载时仅显示“回复评论 #ID”。只有本标签页实际确认删除了目标等确切证据，才能显示“已删除”。评论标题旁“写评论”直接定位输入区或游客登录提示，不清除现有回复目标。输入区聚焦及清空确认打开期间暂停自动追加，离开后恢复，避免输入区被分页推走。用户点回复后定位编辑区，原输入保留；取消回复只解除目标，不清空正文。

保留当前“刚发表的”就地回显：收到 POST 返回 ID 后，在编辑区附近确认本次发布；正文来自本次提交的快照，不伪造服务端时间。滚动时间线加载到相同 ID 后合并，避免重复。此次不改成跳末页，不拉取全部评论寻找目标。

恢复的草稿以轻量提示呈现，明确“已恢复本标签页草稿”，不称云端保存。发布失败不清空输入；回复目标失效时保留正文，要求用户选择目标或明确改成直接评论。手动清空先确认，默认聚焦“继续编辑”，Escape保留草稿；确认后聚焦输入框。主动退出与草稿清理沿用已有规则。

### P06 发帖、注册和登录

发帖区沿“社区 → 标题 → 正文 → 发布”排列，正文区有 Markdown 支持说明但不增加新工具栏；主要按钮为“发布帖子”，“清空草稿”为次要动作且先确认。无草稿时预选有效来源社区，有草稿时不覆盖其社区选择。显示标题、正文和评论计数，与后端 Unicode 字符计数对齐；输入按提交时去掉首尾空白的内容校验，不截断已输入的正文，超限保留草稿。

| 表单 | 已有规则与界面要求 |
| --- | --- |
| 注册 | 用户名 3–64 位英文字母数字；密码 8–20 位不含空格的可打印 ASCII，须同时包含大写字母、小写字母、数字和特殊符号；确认密码一致；成功转登录并带入用户名，不自动登录 |
| 登录 | 仅非空及最长 64；不套用注册最小长度，不修改密码中的空白 |
| 帖子 | 社区必选，标题非空且最多 128 个 Unicode 字符；正文非空且最多 10,000 个 Unicode 字符（源码与 OpenAPI 一致） |
| 评论 | 非空纯文本，最多 2,000 个 Unicode 字符（源码与 OpenAPI 一致）；回复目标可清除；不新增 Markdown 评论或上传按钮 |

输入框有持续可见的标签；说明在输入前可见，错误在字段旁显示并与字段关联；修改字段时清除对应旧错误。登录／注册保留当前页面及原列表来源，登录后继续原流程，不自动提交。提交失败保持输入，聚焦首个错误；加载按钮保持宽度，防止重复提交。登录注册使用 440px 内聚表单，不放空洞宣传侧栏或假第三方登录入口。

### P07 反馈与异常

| 场景 | 内容与动作 |
| --- | --- |
| 首次加载 | 与列表结构一致的静态骨架、简短加载文字；不模拟假帖子 |
| 暂无内容 | “还没有帖子”或“还没有评论”，在用户有可用动作时提供发布入口 |
| 首次读取失败 | 对应区块保留标题、失败原因和重试；不把失败画成空列表 |
| 追加失败 | 已有内容保留，仅尾部出现重试 |
| 请求结果未确认 | 明确“结果未确认，输入已保留”；不提供自动连续重发 |
| 429 限流 | 请求在业务处理前被拒绝，写操作确定未执行：提示“请求过于频繁，请稍后再试”，保留输入，可再次提交；读取不自动重试，按读取失败给出重试；续期被限流按暂时无法续期处理，不当作退出 |
| 403 | 明确没有操作权限，移除错误的操作期待，不抹掉可读内容 |
| 404 | “内容不存在或已不可用”，返回来源/首页；不推断具体删除人 |
| 删除确认 | 展示目标、后果，取消优先获得焦点；确认按钮用危险色，提交中禁止重复 |

## 五 验收标准

- [ ] 六类业务页面和异常页都有对应视觉，现有功能入口没有丢失。
- [ ] 320、390、768、1440px 下可用；手机输入不触发因字体过小导致的缩放；无整页水平溢出。
- [ ] 当前社区、当前排序、投票未知/确认、加载、成功、错误、禁用都有文字或图标信号。
- [ ] 主要交互目标至少 44×44px；键盘可见焦点、菜单关闭与确认取消后焦点恢复正确。
- [ ] 普通文字对比度至少 4.5:1，必要控件边界至少 3:1；200% 文字放大后可读。
- [ ] 列表返回位置、连续加载、删除后的暂停提示、新评论回显、账号草稿隔离保持已有行为。
- [ ] Markdown 安全边界、登录后不自动提交、已发送写请求不自动重放保持不变。
- [ ] 不显示搜索等无接口入口，不显示七日投票期限，不以未知方向冒充未投票。
