## 后端变化与前端处理

| 后端变化 | 前端处理 |
| --- | --- |
| 注册密码 8–20 位不含空格的可打印 ASCII，须同时含大写、小写、数字和特殊符号 | `src/lib/validation.ts` 同步规则与提示；登录校验不变，旧规则注册的账号照常登录 |
| `/api/v1` 按 IP 令牌桶限流，返回 `429 / TOO_MANY_REQUESTS`；注册和登录另有更严的令牌桶 | 新增 `rate-limited` 错误分类；读取不自动重试；写操作确定未执行，提示稍后再试并保留输入 |
| 续期接口同样受限流 | 续期 429 按临时故障（`renew-unavailable`）处理，不立即重试，不判定失效、不清用户名。此前 429 会被归为协议错误并从恢复流程中抛出，可能让会话停在 unknown |
| 投票 429 | 显示“投票没有提交”，不再按结果未确认清除方向并重新查询 |
| 帖子已删除时删除评论返回 404 | 沿用“评论已经不存在”处理，无需改动 |
| 帖子列表 `order` 可省略 | 前端始终显式传入，无需改动 |
| 新增 `http.trusted_proxies` | README 部署说明补充：经 Nginx 反代需配置，否则所有访客共用一个限流桶 |
