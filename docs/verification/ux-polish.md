# 界面层级与交互优化验证

2026-10-05，用户确认从用户任务出发补强被过度弱化的模块，并优化交互。基线为 `/tmp/bluebell-ux-baseline`；本目录没有可用 Git 元数据，使用文件比对。

## 改动与依据

审查现有静态稿的320/390/1440px排版，并对照真实组件。原手机导航隐藏浏览范围，社区名挤占标题；发布入口、热门标题及投票边界过淡。长社区简介默认展开；输入区在评论列表之后；登录未完整携带原页及社区来源；草稿可一步清空。

- 导航使用可辨识的深色文字、选中底色及蓝线；登录与菜单有明确控件边界。菜单依次显示发布、社区、账号。
- 侧栏使用紧凑蓝色发布按钮、16px模块标题、15px热门正文及分区间距，继续复用服务端热度顺序与共享缓存。
- 工具栏显示当前范围；手机标题满宽，社区位于第三行且有至少44×44px触摸区域。整行可打开帖子，社区链接独立；长简介默认收起。
- 登录返回当前页，注册及 RequireAuth 同时携带原列表来源；发帖无草稿时预选仍存在的来源社区，有草稿时不覆盖。所有返回地址继续校验。
- 评论提供“写评论”定位，保留正文和回复目标；输入区聚焦或清空确认打开时暂停新的自动追加，离开后恢复。
- 统一“清空草稿”确认：默认聚焦继续编辑，Escape保留，确认后聚焦标题或评论输入框；修改字段清除对应旧错误。网络写入结果未确认的提示继续保留。
- 投票默认边界清晰；提交时旋转图标、禁用与 aria-busy 配合状态提示，确认后使用勾选、浅底与文字；未知状态不冒充未投票。

真实浏览器复现了快捷定位与分页冲突：30条模拟评论中，点击写评论会触发第二页，输入框的视口y坐标约4052px。暂停编辑期间的自动追加后，第二页未发出，输入框约552px，保持在844px视口内。

## 边界与剩余风险

- 后端未修改、未启动；依赖、锁文件和API契约未变，没有真实业务写入。真实Cookie、后端业务、多设备与触屏软键盘仍需联调。
- GET投票接口无法识别账号的既有限制继续保留，本轮不调用该接口，刷新后的本人方向保持未知。
- 页码分页的并发遗漏等既有限制不变；编辑聚焦不会取消已经开始的读取。
- ESLint仍有3条既有Fast Refresh警告；单JS chunk约596kB，仍有原有构建大小提醒。
